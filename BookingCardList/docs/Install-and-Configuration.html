Booking Card List — Install & Configuration

Proximo 3  ·  Version 0.0.16  ·  June 2026

Booking Card List replaces a standard subgrid of Bookable Resource Bookings with a touch-friendly card board for the Field Service mobile app. This guide covers prerequisites, adding the control to a form, and every configuration property. For day-to-day use by engineers, see the Booking Card List — User Guide.

01Overview

The control shows each Bookable Resource Booking as a card — work order number, incident type, customer, address (as a maps link), start time, estimated travel, products needed, and the booking status with an inline Update status dropdown. Cards are grouped into three tabs (by default Today / Tomorrow / Complete) and laid out responsively. All reads and writes use context.webAPI, so the control also works in the Field Service mobile app while offline.

02Prerequisites

  • A Dynamics 365 Field Service environment with Bookable Resource Bookings and Work Orders.
  • The Booking Card List control imported into the environment (solution Proximo3 Custom Controls).
  • Three saved views of Bookable Resource Bookings (see Tabs & views).
  • Maker access to the form or custom page used by the mobile app, and permission to publish.
  • For offline use: the relevant tables in the mobile offline profile (the default FS profile already includes them).

03Setup — add it to a form

  1. Open the form or custom page used by the mobile app and add a Bookable Resource Booking subgrid (or set the control as a view's grid control).
  2. Select the subgrid → Components → + Add component → Booking Card List.
  3. Enable it for the Phone form factor (and Web / Tablet if wanted).
  4. Set the properties in section 4.
  5. Save, then Publish.

05Tabs & views

The three tabs run three system views of Bookable Resource Bookings, matched by name. The names are fixed in the control:

My Bookings - Today
My Bookings - Tomorrow
My Bookings - Completed
  • Create those three views, filtered however you like (e.g. current user's resource and date range, or completed in the last N days). The control reads each view's FetchXML and runs it, so each tab reflects exactly that view's filter and sort.
  • The Tab 1/2/3 Name properties change only the labels, not which view runs.
Tip. If a tab is empty, the view name almost certainly does not match exactly — check for a hyphen vs en-dash and stray spaces.

06Custom fields

Extra Field 1–3 show up to three extra columns on each card. Enter a column logical name; the field's value is shown (no caption), and the row is hidden when the property is blank or the value is empty.

  • Default source is the booking (bookableresourcebooking) — e.g. prx3_priority.
  • Prefix with workorder. (or wo.) to read from the related Work Order, e.g. workorder.msdyn_instructions.
  • For a lookup column, enter its _logicalname_value form (e.g. _prx3_site_value).
  • Set Custom Fields Heading to show one caption (styled like Est. Travel) above the values.
Important. The prefix is a fixed keyword — workorder/wo or booking/brb — not the table's logical name. Use workorder.msdyn_instructions, not msdyn_workorder.msdyn_instructions.
You enterShows
workorder.msdyn_instructionsThe work order's Instructions text.
prx3_priorityThe booking's Priority choice (formatted label).
_prx3_site_valueThe booking's Site lookup (the related record's name).

07Troubleshooting

IssueResolution
A tab is emptyThe view name does not match the fixed names exactly (hyphen vs en-dash, spaces). Fix the view name.
A custom field does not showCheck the column logical name and prefix (workorder. for work order fields); confirm the record has a value. Lookups need the _logicalname_value form.
Changes do not appear after deployThe mobile app caches control bundles — hard-refresh (Ctrl+Shift+R) or reopen the app. The version is raised each release to clear the cache.
Errors are not visibleThe control logs [BookingCardList] … to the browser console (F12) and shows a red banner on the card area.
